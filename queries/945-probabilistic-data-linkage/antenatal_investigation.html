2025-11-27

Data overview

We have the following information about fields in the dataset:

  • Visit date- This should occur several times as we expect mothers to have different visit dates throughout their pregnancy.
  • Client_no- These are retained throughout the visits, but we have noticed that they are sometimes reassigned to other mothers, i.e, 3 mothers with client number 189 in all visits.
  • Last name- mother’s name, but it’s possible for people to have similar names.
  • First name- mother’s first name, but possible to have similar names.
  • Client contacts- We have missing data on contacts. Some mothers don’t possess phones
  • Ageyrs- Participant age at visit date. This should be constant or 1 year added.
  • Location- district, parish, and village should be similar. But someone can shift.
  • Ancvisit- the visit number should change with the visit date.
  • Anc_parity and anc_parity2- parity is usually recorded as 4+0, 4+1. During data entry, this was separated and 4 (anc_parity) and 0 (anc_parity2).
  • Anc_gravity- should be constant throughout the visits.
  • Anc_gestationalage- should change with the visit number and visit date..
  • Anc_height- should be similar throughout the visits.
  • Expected date - delvry_day, expected_mmdlvry, and expected_yrdlvry should be similar or slightly different for all visits.

First, some data cleaning:

  • Replaced all “NIL” values with NA: need to confirm if that is correct?
  • Removed visit dates that were in the future
  • Created a new variable for expected delivery date based on the day, month, and year
anc_clean <- anc_sharedhashed %>% 
  # Filter just to the relevant columns
  select(all_of(rel_cols)) %>%
  mutate(
    # Replace visit days in the future with NA
    visit_date = if_else(visit_date > today(), 
                              NA_POSIXct_,
                              as.POSIXct(visit_date)),
    # Replace expected delivery years way in the future with NA
    expected_yrdlvry = if_else(expected_yrdlvry > year(today()) + 5,
                               NA_integer_,
                               expected_yrdlvry)
    ) %>% 
  # Replace all "NIL" with NA
  mutate_if(is.character, ~na_if(., "NIL")) %>%
  # Clean expected delivery month
  # Get the first three letters & convert to month number
  mutate(expected_mmdlvry = match(substr(expct_mmdlvry, 1, 3),
                                  month.abb)) %>% 
  # Clean expected delivery year
  # Some of the years are just 2 digits- convert to 4 digits
  mutate(expected_yrdlvry = ifelse(nchar(expected_yrdlvry) == 2,
                                   as.numeric(paste0("20", expected_yrdlvry)),
                                  expected_yrdlvry)) %>%
  mutate(
    # Add a column to keep track of which visits are mapped to which patient
    record_id = row_number(),
    # Add a column for expected delivery date based on day, month, and year
    expected_delivery_date = case_when(
      !is.na(delvry_day) & !is.na(expected_mmdlvry) & !is.na(expected_yrdlvry) ~
        make_date(year = as.integer(expected_yrdlvry),
                  month = as.integer(expected_mmdlvry),
                  day = as.integer(delvry_day)),
      TRUE ~ NA_Date_
    ),
    # Make sure numeric variables are numeric
    ageyrs = as.numeric(ageyrs),
    anc_gravida = as.numeric(anc_gravida),
    anc_parity  = as.numeric(anc_parity),
    anc_parity_2 = as.numeric(anc_parity_2),
    # Clean the location variables
    distr_clean   = tolower(distr),
    parish_clean  = tolower(parish),
    village_clean = tolower(village1)
  ) %>%
  # Create a numeric column for expected delivery date
  # Days since 2020-01-01
  mutate(numeric_delivery_date = as.numeric(expected_delivery_date - as.Date("2020-01-01")))

Attempt at probabilistic data linkage

I am using the R package fastLink to try to match records probabilistically based on the fields you designated as informative. Since the data has been anonymised via hashing, I can no longer do a “fuzzy match” on the name or contact columns, e.g. something that would allow me to match “Jonathan” with “Johnathan” or a phone number with a missing digit. I am instead treating those fields as exact matches. We can potentially revisit this issue later if you end up wanting to run the matching code yourself with access to the unmodified data.

I am matching in the following way:

Exact matches:

  • First name
  • Last name
  • Client contact
  • Client number

Numeric matches:

  • Age in years
  • Gestational age
  • Gravity
  • Height
  • Expected delivery date (measured in days since 2020-01-01)

Now we can examine the output of the matching procedure. The fastLink function returns a list with several components, including the matched pairs and the estimated parameters of the matching model. We are only getting pairs with a match probability of at least 85% (which is a parameter we can adjust if needed).

# Extract matched pairs
matched_pairs <- data.frame(a = as.character(fl_out$matches$inds.a),
                            b = as.character(fl_out$matches$inds.b),

# Build the graph
g <- graph_from_data_frame(d = matched_pairs,

clusters <- components(g)

patient_id_map <- data.frame(
  record_id = names(clusters$membership),

anc_matched <- anc_clean %>%

records_per_patient <- anc_matched %>%
